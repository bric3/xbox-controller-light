# USB reference

[Analysis](analysis.md) | [Bluetooth](bluetooth-macos.md) | [Firmware](firmware.md)

Hardware results recorded 2026-10-15: Series X|S `045e:0b12`, USB-C,
installed firmware `5.9.2709.0` read separately over Bluetooth.

## Device and support

| Property                 | Observed value                                                     |
| ------------------------ | ------------------------------------------------------------------ |
| USB product / speed      | `Controller`; full speed, 12 Mbit/s                                |
| Device release           | `0x0509`; separate from the full firmware version                  |
| Device owner             | Apple's `XboxUSBDevice`                                            |
| Interface 0 owner        | `XboxSeriesXGamepad`                                               |
| Class/subclass/protocol  | `ff/47/d0`                                                         |
| Interrupt endpoints      | `02` OUT, `82` IN; 64 bytes                                        |
| Other alternate settings | Audio and bulk endpoints; no declared USB DFU interface            |
| LED control              | Off, steady brightness and host-generated glow visually confirmed  |
| Retention                | Brightness lost after unplugging USB and switching to Bluetooth    |
| Firmware readback        | No verified protocol; no dump obtained                             |

## LED utility

[tools/XboxUsbLed.java](../tools/XboxUsbLed.java) uses Java 25 FFM, IOKit and
CoreFoundation. It requires exactly one supported USB or Bluetooth controller.
The USB implementation uses shared HID access and leaves Apple's driver attached.

```sh
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --self-test
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --inspect
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --brightness 10
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --increment
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --decrement 5
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --glow
mise exec java@corretto-25 -- jbang tools/XboxUsbLed.java --off
```

| Operation                    | Behaviour                                                         |
| ---------------------------- | ----------------------------------------------------------------- |
| `--on` / `--off`             | Step 20 / zero                                                    |
| `--brightness N` or bare `N` | Integer step 0-47                                                 |
| `--increment [N]`            | Last accepted value plus 1, or plus `N` from 1 to 47              |
| `--decrement [N]`            | Last accepted value minus 1, or minus `N` from 1 to 47            |
| `--glow`                     | Steps 0-20, three-second cosine cycle, 50 ms between writes, 30 s |
| Glow completion              | Send off; sequence numbers increment and remain non-zero          |
| `--inspect`                  | Identify transport without writing                                |
| `-h`, `--help`, no arguments | Help; exit 0 without loading native frameworks                    |
| Invalid arguments            | Exit 2, short error, no write; values are never clamped           |
| Bluetooth LED request        | Exit 1, unsupported; no USB write or USB cache change             |

Steady commands return immediately. Glow is generated by host writes; built-in
firmware animation modes have not been visually tested. Hardware access from the
agent sandbox required an execution exception; ordinary Terminal use requires no
`sudo`. No firmware, pairing or calibration commands are sent.

### Relative state and retention

Cache: `~/Library/Caches/xbox-light/usb-led.state`.

| Stored or checked value | Purpose                                                    |
| ----------------------- | ---------------------------------------------------------- |
| Last accepted step      | Baseline for relative adjustment                           |
| Live HID registry ID    | Reject a baseline after reconnecting                       |
| macOS boot-session UUID | Reject a baseline after restarting                         |
| File lock               | Serialise commands from this utility                       |
| Atomic replacement      | Store completed settings                                   |
| Pre-write invalidation  | Require an absolute setting after an interrupted operation |

1. Set an absolute brightness after reconnecting or restarting.
2. Use relative adjustments while the connection remains valid.
3. Reapply an absolute value after an interrupted command.

> [!IMPORTANT]
> The cache is host state. It provides no live readback and cannot detect changes
> made by other software. Brightness does not survive unplugging USB.

Step 20 is host policy; factory brightness is unknown. The firmware's separate
[EEPROM-backed timing values](firmware.md#defaults-and-saved-configuration)
do not establish a persistent brightness command. Unplugging with batteries
fitted can leave the controller powered; complete power removal was not tested
separately. USB brightness step 5 was visually reconfirmed after transport
selection was added.

## macOS HID framing

```mermaid
flowchart LR
    App[Java FFM] --> Report[Output report ID 1, 13 bytes]
    Report --> Series[XboxSeriesXGamepad]
    Series --> Wireless[XboxWirelessGamepad.setReport]
    Wireless --> HID[XboxHIDDevice.setReport]
    HID --> Pipe[IOUSBHostPipe.AsyncIO]
    Pipe --> Controller[Controller GIP parser]
```

| Driver location             | Observed behaviour                                                        |
| --------------------------- | ------------------------------------------------------------------------- |
| `0x10000dc44`               | `XboxWirelessGamepad::setReport`; checks low byte of report ID            |
| `0x10000deb4`-`0x10000dee0` | ID `1` requires 13 bytes; ID `5` requires 5 bytes                         |
| `0x100009dc8`               | `XboxHIDDevice::setReport`; forwards descriptor without rebuilding header |
| `0x10000a9a0`               | `XboxWirelessGamepad::getReport`; always `0xe00002c7`, unsupported        |

Working LED-off buffer:

```text
HID report type: output
HID metadata report ID: 1
Buffer length: 13
Buffer: 0a 20 01 03 00 00 00 00 00 00 00 00 00
        ----------- GIP ----------- + six trailing zero bytes
```

The GIP opcode is `0x0a`, with declared payload length 3. HID metadata report ID
`1` selects Apple's output handler. The six trailing zeros satisfy its length check.

### GIP packet

Steady step 10 before USB padding:

```text
0a 20 01 03 00 01 0a
```

| Byte | Meaning                                           |
| ---- | ------------------------------------------------- |
| `0a` | LED command                                       |
| `20` | Internal-command flag                             |
| `01` | Non-zero sequence                                 |
| `03` | Payload length                                    |
| `00` | Required leading payload byte                     |
| `01` | Steady mode; `00` switches off                    |
| `0a` | Intensity step 10; documented protocol range 0-47 |

See [firmware dispatch](firmware.md#the-command-and-its-path) for the recovered
LED-task and PWM path, and Microsoft's
[LED command specification](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gipusb/ec312389-2e05-4915-85ed-0e8fe9c3d33b)
for protocol units. No optical brightness curve was measured.

## Raw USB experiment

[tools/XboxUsbRawLed.java](../tools/XboxUsbRawLed.java) retains the earlier libusb
experiment. It validates identity, class and endpoints, captures the interface,
sends START `05 20 01 01 00` and LED commands, then releases and requests driver
reattachment in cleanup.

> [!WARNING]
> Raw USB capture requires administrator authentication on this Mac and interrupts
> system controller input. Driver reinitialisation can reset brightness. Use the
> shared HID utility for normal control.

| Test                    | Recorded result                                      |
| ----------------------- | ---------------------------------------------------- |
| First authenticated run | START transferred 5 bytes; LED transferred 7 bytes   |
| Raw breathing           | 525 brightness writes; glow visually confirmed       |
| Cleanup                 | Interface release and driver reattachment succeeded  |

## Firmware readback attempt

| Step | Operation                                           | Result                                                              |
| ---- | --------------------------------------------------- | ------------------------------------------------------------------- |
| 1    | `ioreg -r -n Controller -l -w 0`                    | Confirmed identity and Apple driver ownership                       |
| 2    | Java FFM probe, Homebrew libusb 1.0.30              | Sandbox enumerated no devices; unsandboxed probe opened controller  |
| 3    | `GET_DESCRIPTOR`: `80 06 00 02 00 00 00 10`         | 119-byte configuration descriptor                                   |
| 4    | `libusb_claim_interface(handle, 0)`, no detach      | `-3 (LIBUSB_ERROR_ACCESS)`                                          |
| 5    | Installed ARM64 driver inspection                   | `getReport` always returns `kIOReturnUnsupported`                   |

Configuration descriptor SHA-256:

```text
5455aacefefdf3610b06f156585cfef4c6dae8e06e92cdb9a591f1f3e9ed2a2c
```

Driver: `/System/Library/DriverExtensions/XboxGamepad.dext/XboxGamepad`, SHA-256:

```text
9e795737a95f163ddfca815cf9813c3391e6a1116d9150adb7300288b7704b9b
```

The initial readback attempt sent only standard descriptor requests, with no
firmware updates, resets, pairing changes, calibration changes or driver detachments.
Handles and the libusb context were closed. USB descriptors contain no firmware image.

Microsoft's [GIP message summary](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gipusb/c66cee2f-7728-4ec1-8f3c-e9ab3aa4d696)
does not specify flash readback. The independent
[protocol notes](https://gist.github.com/TheNathannator/c5d3b41a12db739b7ffc3d8d1a87c60a)
label `0x0c` as firmware data without establishing a read operation.
No guessed firmware commands were sent. Extraction requires both device access
and a verified readback protocol; neither raw access nor an updater download
establishes a flash dump.

### Native capture helper

[tools/XboxUsbCapture.java](../tools/XboxUsbCapture.java) provides an alternative
IOUSBHost capture experiment. It requires exactly one `045e:0b12` controller and
an explicit `--capture` argument. Cleanup calls `destroy` to release ownership
and restore matching; the SDK documents a USB reset during cleanup.

```sh
mise exec java@corretto-25 -- jbang tools/XboxUsbCapture.java --self-test
mise exec java@corretto-25 -- jbang tools/XboxUsbCapture.java --inspect
```

Self-tests passed and inspection found one controller. Its privileged capture
mode was not exercised; the later raw LED success used libusb instead.
This helper sends no GIP commands and does not dump firmware.
